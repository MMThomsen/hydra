Analysis:
TEST 2 demonstrates the key to making regex p1* p2 succeed:

Comparing TEST 1 vs TEST 2 at event 0:0:
- TEST 1 @2: {p1(Alice), p2(Alice)} → regex FAILS (0:0 false)
- TEST 2 @2: {p2(Alice)} only → regex SUCCEEDS (0:0 true)

The critical difference:
- When target event has BOTH p1 AND p2 simultaneously → FAILS
- When target event has ONLY p2 (p1 earlier in path) → SUCCEEDS

This suggests the regex semantics require:
1. Path from current event through intermediate events where p1 holds
2. Target event must satisfy p2 WITHOUT p1 present
3. The p1* must "terminate" before the final p2

Pattern that works:
- Event i: p1(x) [start of p1*]
- Event i+k: p1(x) [continuing p1*]
- Event j: ONLY p2(x) [end, p1* terminated]

Pattern that fails:
- Event j: p1(x) AND p2(x) [both present = ambiguous]

This interpretation aligns with regex automaton semantics where the Kleene
star p1* consumes p1 events, then transitions to p2 state which must see
p2 WITHOUT p1 (clean transition).

Expected results updated based on this understanding.
